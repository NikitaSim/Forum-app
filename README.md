# лабораторной работы № 2

 В лабораторной № 2 слой хранение переведено на PostgreSQL через Spring Data JPA.

## Слои приложения

1. `models` — JPA-сущности и связи.
2. `repository` — интерфейсы `JpaRepository`, в том числе методы фильтрации.
3. `service` — бизнес-логика, проверки и транзакции.
4. `api` — REST-контроллер, DTO и обработчик ошибок.
5. `config` — настройки Spring Security и BCrypt `PasswordEncoder`.

## База данных

`init.sql` создаёт таблицы, внешние ключи, уникальные ограничения, проверки и индексы. Таблица `thread_tags` использует составной первичный ключ `(thread_id, tag_id)`, поэтому каждая связь тега и треда уникальна. Hibernate управляет объектным отображением, но создание схемы выполняется SQL-скриптом.

## Hibernate и Spring Data JPA

JPA — спецификация ORM, Hibernate — её реализация, Spring Data JPA предоставляет репозитории и производные запросы. Репозитории наследуют `JpaRepository`, а `@EntityGraph` используется для загрузки связанных сущностей, нужных REST-ответам, чтобы избежать ошибок доступа к ленивым связям после завершения транзакции.

## DTO и REST

Запросы принимаются в DTO с Jakarta Validation. В ответах пароль не возвращается. Контроллеры реализуют CRUD и фильтрацию. Ошибки валидации и бизнес-правил преобразуются в HTTP 400.

## Пароли и аутентификация

Пароли кодируются BCrypt. Эндпоинты регистрации и входа доступны по `/api/auth/register` и `/api/auth/login`. Полноценная JWT-аутентификация и разграничение доступа по ролям не реализованы; для лабораторной REST CRUD API пока разрешён без токена.

## Тестирование

Unit-тесты сервисов используют Mockito. `ForumApplicationTests` запускает Spring Boot контекст, исключая создание `DataSource`, Hibernate и Spring Data репозиториев; вместо репозиториев предоставляются mock-объекты. Таким образом тесты не подключаются к PostgreSQL и не меняют данные в БД.
