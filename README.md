# Forum App — Лабораторная работа № 4

## 1. Описание проекта

**Forum App** — REST API приложения для работы с форумом. Приложение позволяет пользователям регистрироваться, создавать тематические обсуждения, публиковать посты, оставлять комментарии и голосовать за публикации.

В рамках четвёртой лабораторной работы подключён Spring Security (JWT-токены, роли ADMIN / MODERATOR / USER) и настроено логирование в консоль и файл. Также подключён Swagger UI для документации API. Ранее реализованы централизованная обработка исключений и разделение API на отдельные контроллеры.

## 2. Используемые технологии

- **Java** — основной язык разработки.
- **Spring Boot** — создание и настройка приложения.
- **Spring Web** — реализация REST API.
- **Spring Data JPA** — взаимодействие с базой данных.
- **Hibernate** — ORM и управление сущностями.
- **PostgreSQL** — реляционная база данных.
- **Jakarta Validation** — проверка входных данных.
- **Lombok** — сокращение шаблонного кода.
- **JUnit 5** — модульное тестирование.
- **Mockito** — создание mock-объектов для тестирования.
- **Spring Security + JWT (jjwt)** — аутентификация по токенам и разграничение прав по ролям.
- **Logback / SLF4J** — логирование в консоль и файл.
- **springdoc-openapi (Swagger UI)** — документация REST API.
- **Maven** — сборка и управление зависимостями.
- **Postman** — ручное тестирование REST API.

## 5. Обработка исключений

В рамках лабораторной работы реализована централизованная обработка исключений с помощью аннотаций `@RestControllerAdvice` и `@ExceptionHandler`.

Это позволяет отделить обработку ошибок от бизнес-логики контроллеров и возвращать клиенту единообразные ответы.

### Собственные исключения

В пакете `exception` реализованы следующие классы:

| Исключение | Назначение |
|---|---|
| `ResourceNotFoundException` | Базовое исключение для отсутствующих ресурсов |
| `UserNotFoundException` | Пользователь не найден |
| `ThreadNotFoundException` | Тред не найден |
| `PostNotFoundException` | Пост не найден |
| `CommentNotFoundException` | Комментарий не найден |
| `VoteNotFoundException` | Голос не найден |
| `InvalidRequestException` | Некорректные входные данные |
| `InvalidCredentialsException` | Неверные учётные данные |
| `DuplicateResourceException` | Конфликт уникальности данных |
| `UserHasDependenciesException` | Невозможно удалить пользователя из-за связанных записей |

### Централизованный обработчик

Класс `RestExceptionHandler` отвечает за преобразование исключений в HTTP-ответы.

Для всех ошибок используется единый формат ответа `ApiError`, содержащий:

- `timestamp` — время возникновения ошибки;
- `status` — HTTP-статус;
- `error` — название ошибки;
- `message` — описание проблемы;
- `path` — адрес запроса;
- `solution` — рекомендация по устранению ошибки;
- `details` — дополнительные сведения, например ошибки валидации.

### Используемые HTTP-статусы

| Статус | Назначение |
|---|---|
| `200 OK` | Запрос выполнен успешно |
| `201 Created` | Ресурс успешно создан |
| `204 No Content` | Ресурс успешно удалён |
| `400 Bad Request` | Некорректный запрос или ошибки валидации |
| `401 Unauthorized` | Ошибка авторизации |
| `404 Not Found` | Запрашиваемый ресурс не найден |
| `409 Conflict` | Конфликт данных или ограничений базы |
| `500 Internal Server Error` | Внутренняя ошибка сервера |

### Пример ответа при ошибке

```json
{
  "timestamp": "2026-11-10T22:30:00",
  "status": 404,
  "error": "Not Found",
  "message": "Пользователь с ID 15 не найден.",
  "path": "/api/users/15",
  "solution": "Проверьте идентификатор ресурса и убедитесь, что запись существует.",
  "details": []
}
```

## 6. Особенности удаления пользователей

Удаление пользователя проверяется на наличие связанных записей.

Если пользователь является автором тредов, постов или комментариев, приложение не удаляет его автоматически, чтобы избежать потери пользовательского контента.

Вместо этого возвращается `409 Conflict` с описанием причины и количеством связанных записей.

## 7. Запуск приложения

### Требования

Перед запуском необходимо установить:

- JDK версии, соответствующей настройке проекта в `pom.xml`;
- PostgreSQL;
- Git (при необходимости клонирования репозитория).

### Настройка базы данных

Необходимо создать базу данных PostgreSQL и указать параметры подключения в `application.properties`.

Пример конфигурации:

```properties
spring.datasource.url=jdbc:postgresql://localhost:5432/forum
spring.datasource.username=postgres
spring.datasource.password=your_password

spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
```

Значения параметров подключения необходимо заменить на соответствующие настройки локальной базы данных.

### Запуск

В корневой директории проекта выполните:

```bash
.\mvnw.cmd clean
```

Затем запустите приложение:

```bash
.\mvnw.cmd spring-boot:run
```

Также при наличии настроенного Makefile можно использовать:

```bash
make run
```

После успешного запуска приложение будет доступно по адресу:

```text
http://localhost:8080
```

Базовый адрес REST API:

```text
http://localhost:8080/api
```

## 8. Spring Security и роли (лабораторная № 4)

Используется JWT: `POST /api/auth/login` проверяет логин и пароль и возвращает токен (HS256, в нём имя пользователя и роль). Токен передаётся в заголовке `Authorization: Bearer <token>`. Роль при каждом запросе перечитывается из БД. Пользователи и роли хранятся в таблице `users`, пароли — в виде BCrypt-хэшей. Сессии не используются (stateless). Секрет и срок жизни токена задаются в `application.properties` (`JWT_SECRET`, не короче 32 символов, и `JWT_EXPIRATION_MINUTES`, по умолчанию 60).

При первом запуске автоматически создаётся администратор (`AdminInitializer`): логин `admin`, пароль `admin123`. Значения можно изменить переменными окружения `ADMIN_USERNAME`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`. Регистрация через `/api/auth/register` создаёт пользователя с ролью `USER`.

| Операция | Доступ |
|---|---|
| `/api/auth/**`, Swagger UI | без авторизации |
| `GET /api/users/**` | ADMIN, MODERATOR |
| `POST`, `PUT`, `DELETE /api/users/**` | ADMIN |
| `DELETE` для тредов, постов, комментариев, голосов | ADMIN, MODERATOR |
| остальные методы `/api/**` | любой авторизованный пользователь |

Ошибки безопасности возвращаются в формате `ApiError`: `401 Unauthorized` — токен отсутствует, неверен или просрочен, `403 Forbidden` — недостаточно прав.

Пример запроса:

```bash
curl -X POST http://localhost:8080/api/auth/login -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}'

curl http://localhost:8080/api/users -H "Authorization: Bearer <token>"
```

## 9. Логирование

Логирование выполняется через SLF4J + Logback (`logback-spring.xml`):

- в консоль;
- в файл `logs/forum.log` (ротация по дням и по размеру 10 МБ, хранится 14 дней). Каталог можно изменить переменной `LOG_DIR`.

Логируются запросы к API (`RequestLoggingFilter`), операции контроллеров и сервисов, неудачные попытки входа, ошибки 401/403 и все обработанные исключения (`RestExceptionHandler`). Уровень пакета `com.example.forum` задаётся в `application.properties`.

## 10. Swagger (OpenAPI)

После запуска документация доступна по адресам:

- Swagger UI: `http://localhost:8080/swagger-ui.html`
- OpenAPI JSON: `http://localhost:8080/v3/api-docs`

Методы сгруппированы по контроллерам (теги), параметры и модели описаны, для каждого метода указаны возможные коды ответов. Для проверки защищённых методов получите токен через `/api/auth/login`, нажмите **Authorize** и вставьте токен.
